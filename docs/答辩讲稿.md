# 答辩讲稿

## 1. 开场

各位老师好，我的课程设计题目是《基于 Ollama 的本地大模型部署与多轮对话情感六元组抽取应用开发》。我完成了本地 Ollama 部署、情感六元组抽取系统、Gradio 演示界面、公开数据集评测、模型对比和 Prompt 策略对比。

## 2. 任务定义

我的任务输入是一段评论或多轮对话。输出是结构化情感六元组：说话人、评价对象、评价方面、观点词、情感极性、文本理据。系统还检测同一说话人对同一对象和方面的情感转折。这个任务比普通情感分类更细，能回答“谁对什么方面表达了什么观点，依据是什么，态度是否改变”。

## 3. 技术路线

系统使用 Ollama 在本地运行大模型。主模型是 `qwen2.5:7b`，对比模型是 `llama3.1:8b` 和 `qwen2.5:3b`。我设计了四步链式 Prompt：第一步抽取目标和方面，第二步抽取说话人和观点，第三步推理情感和理据，第四步检测情感转折。每一步都要求模型返回 JSON，并通过程序进行 JSON 提取、修复和字段规范化。

## 4. 系统演示顺序

1. 打开 `python app.py` 启动的 Gradio 页面。
2. 点击“检查 Ollama”，展示本地模型列表。
3. 输入中文酒店服务多轮对话。
4. 选择 `qwen2.5:7b` 和 `four-step`。
5. 展示六元组表格、情感转折表格和完整 JSON。
6. 展示导出的 `outputs/web_demo_result_zh.json`。
7. 切换到 `one-shot` 或 `qwen2.5:3b`，说明质量、稳定性和时延差异。

## 5. 实验设计

公开评测使用 ASTE-Data-V2，评价三元组 Precision、Recall、F1 和情感准确率。系统工程质量使用 JSON 有效率和平均推理时延。多轮对话情感转折使用 30 条人工金标样例，评价 flip precision、flip recall 和 flip F1。模型对比覆盖 `qwen2.5:7b`、`llama3.1:8b`、`qwen2.5:3b`，Prompt 对比覆盖一次性抽取和四步链式抽取。

正式 120 条公开评测结果如下：one-shot 中 `qwen2.5:7b` F1 为 0.5844，`llama3.1:8b` 为 0.5632，`qwen2.5:3b` 为 0.5325，三者 JSON 有效率均为 1.0000。four-step 中 `qwen2.5:7b` F1 为 0.5682，Recall 为 0.6328，JSON 有效率为 0.9500；`qwen2.5:3b` 平均时延最低，为 18.99 秒。公开短文本评测中 one-shot 的 F1 更高，系统现场主流程采用 four-step，因为它的中间步骤更清晰，召回率和多轮对话展示更适合答辩解释。30 条转折评测的 flip F1 为 0.1333，这个结果用于说明多轮态度变化检测仍是系统的主要难点。

## 7. 常见问题回答

问：为什么选择情感六元组抽取？

答：它属于情感分析任务，同时比整体情感分类提供更细粒度的信息，能体现大模型对对象、方面、观点、理据和转折的结构化理解能力。

问：为什么采用四步 Prompt？

答：四步 Prompt 把复杂任务拆成目标识别、观点绑定、情感推理和转折检测，中间结果清晰，便于错误定位和答辩展示。

问：为什么用 Ollama？

答：Ollama 提供本地模型部署、统一 API 和模型管理能力，适合课程要求中的本地大模型部署。

问：模型对比的意义是什么？

答：模型对比能验证结果稳定性，也能分析质量、速度和 JSON 有效率之间的权衡，直接对应评分细则中的加分挑战。

问：为什么主模型选择 `qwen2.5:7b`？

答：它在 four-step 评测中取得最高 F1、最高 Recall 和最高情感准确率，并且中文样例能稳定输出说话人、对象、方面、观点和转折结果。

问：one-shot 和 four-step 的结论是什么？

答：one-shot 在 ASTE 单句评论中 F1 更高、速度更快；four-step 中间结果更清晰，适合展示系统设计和错误定位。

问：中文对话能处理到什么程度？

答：中文酒店样例输出 `valid_json=true`，得到 5 条六元组和 1 条情感转折，结果保存在 `outputs/web_demo_result_zh.json`。

问：系统的主要不足是什么？

答：边界匹配仍然依赖模型输出，例如目标和方面可能被合并；情感转折检测仍然偏弱，后续可以通过更严格的 schema 解码、少量标注数据和转折样例微调提升一致性。
